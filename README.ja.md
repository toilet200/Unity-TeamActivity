# Team Activity

[English](README.md) | 日本語

Team Activityは、各メンバーが現在作業しているScene、Prefab、C#スクリプトなどをUnity Editor内で共有し、マージコンフリクトにつながる作業の重複を事前に知らせる軽量なEditor拡張です。

このツールが提供するのは、作業を妨げないソフトロックです。プロジェクト内のファイルを読み取り専用にしたり、ほかのメンバーによる編集を強制的に禁止したりすることはありません。

## 注意

- 本ツールのスクリプトは、Codexによって作成されたものです。
- 本ツールは、Unity専用となっています。

## 主な機能

- メンバーのOnline、Idle、Offline表示
- 現在開いているSceneの表示
- 自動選択または固定したPrefab・C#スクリプトの表示
- 複数人が同じSceneやアセットを報告した場合のConflict Risk警告
- メンバーごとの短いNote共有
- ローカルで変更されているGitファイルの表示（任意）
- Unityプロジェクトごとに分離された設定と保存領域
- 同じメンバーが複数のPCを使う場合のデバイス識別
- Dropbox、Google Drive、NAS、ネットワーク共有フォルダーに対応するファイルシステム方式
- 将来Supabase、Firebase、独自バックエンドへ置き換えやすい通信インターフェース

## 必要環境

- Unity 6000.0以降
- 複数PCで使う場合、全メンバーがアクセスできる共有フォルダー
- Git変更表示を使用する場合のみ、ローカルで利用可能なGit

このパッケージはEditor専用であり、プレイヤービルドへコードを追加しません。

## インストール

### Unity Package Managerから導入

1. Unityで`Window > Package Manager`を開きます。
2. `+`ボタンをクリックします。
3. `Install package from git URL...`を選択します。
4. 次のURLを入力します。

   ```text
   https://github.com/toilet200/Unity-TeamActivity.git
   ```

5. インポート完了後、`DevTools > Team Activity`を開きます。

### Embedded packageとして導入

リポジトリを対象Unityプロジェクトの次の場所へコピーすることでも導入できます。

```text
Packages/com.devtools.team-activity
```

## チームの初期設定

1. `DevTools > Team Activity`を開きます。
2. `Settings`を開きます。
3. メンバー名とデバイス名を入力します。
4. チームで使用する共有親フォルダーを選択します。
5. `Save settings and reconnect`をクリックします。
6. すべてのメンバーのPCで同様に設定します。

選択するのは共有親フォルダーです。その中に自動生成されるプロジェクト専用フォルダーを直接選択しないでください。

例：

```text
TeamActivity/                         <- このフォルダーを選択
└─ My Unity Project-a1b2c3d4/         <- 自動生成
   ├─ <client-id>.presence.json
   └─ <client-id>.presence.json
```

各PCでローカルパスや親フォルダーの表示名が異なっていても構いません。同じ同期対象またはネットワーク共有フォルダーを参照していることが重要です。共有フォルダーはプロジェクトの`Assets`外に配置してください。

初期値の`Library/TeamActivity`は1台のPCでの動作確認に使用できますが、ほかのPCとは共有されません。

## 基本操作

### 作業対象の自動表示

ProjectウィンドウでPrefabまたはC#スクリプトを選択すると、現在の作業対象として自動的に共有されます。

### 作業対象の固定

アセットを選択して`Pin selection`を押すと、別のオブジェクトを選択しても作業対象として表示し続けます。自動選択へ戻す場合は`Use automatic`を押します。

### Note

Note欄には「ボスの攻撃タイミングを調整中」のような短い作業内容を入力できます。Noteはほかの在席情報と一緒に共有されます。

### Conflict Risk警告

Offlineではない複数のメンバーが同じScene、Prefab、C#スクリプトを報告すると、`Conflict Risk`警告が表示されます。これは注意を促すだけのソフトロックであり、アセットの編集や保存を禁止しません。

## ステータス判定

| ステータス | 判定 |
| --- | --- |
| Online | heartbeatとUnity Editor上の操作が新しい状態 |
| Idle | heartbeatは届いているが、2分間追跡対象の操作がない状態 |
| Offline | heartbeatが30秒間届いていない状態 |

heartbeatは5秒ごとに送信されます。Unityを正常終了した場合はすぐにOfflineを報告します。クラッシュ、通信切断、クラウド同期の遅延時はOffline判定時間を使用します。

## Git変更ファイル表示

`Show Git changes`を有効にすると、ローカルのGit作業ツリーを定期的に確認し、変更されているファイルパスを共有します。この機能は任意です。Gitが利用できない場合やGitリポジトリではない場合も、Team Activityのほかの機能は引き続き動作します。

## プロジェクトごとの分離

Unityの安定した`productGUID`を使用し、プロジェクトごとに専用の保存フォルダーとEditor設定を作成します。同じUnityプロジェクトのクローンは同じ在席グループを利用し、無関係なプロジェクトは同じ共有親フォルダーを指定しても分離されます。

## 保存情報とプライバシー

標準のファイルシステム方式では、クライアントごとに小さなJSONファイルを1つ保存します。現在の作業状況に応じて、次の情報が含まれます。

- プロジェクト名とプロジェクト識別子
- メンバー名とデバイス名
- クライアント識別子
- heartbeatと最終操作時刻
- 開いているSceneのパス
- 選択または固定したアセットのパス
- Noteの内容
- ローカルで変更されているGitファイルのパス

Team Activity自身のサーバーへデータを送信することはありません。クラウド同期フォルダーを選択した場合、データは利用するサービスとその共有権限に従って扱われます。

## 既知の制限

- クラウド同期が遅れると、一時的にメンバーがOfflineに見える場合があります。
- ソフトロックは警告であり、排他的なファイルロックではありません。
- 対応するプロジェクトアセットの選択状態を追跡しますが、外部コードエディター内で開いているファイルは検出しません。
- 全メンバーが同じ共有フォルダーへアクセスできる必要があります。
- ファイルシステム方式は小規模チームの軽量な在席情報向けであり、Sceneのリアルタイム共同編集機能ではありません。

## トラブルシューティング

### ほかのメンバーが表示されない

- 全員が同じ共有フォルダーを選択しているか確認してください。
- 同期サービス上でプロジェクト専用フォルダーの同期が完了しているか確認してください。
- 全員が同じUnityプロジェクトのクローンを開いているか確認してください。
- `Refresh`または`Save settings and reconnect`を実行してください。

### 一時的にOfflineになる

共有フォルダーの同期に30秒以上かかり、最新のheartbeatファイルが届いていない可能性があります。

### Git変更ファイルが表示されない

Gitがインストールされていること、UnityプロジェクトがGitリポジトリ内にあること、`Show Git changes`が有効であることを確認してください。

## バックエンドの差し替え

`ITeamActivityTransport`によって、在席情報の保存処理をEditor UIや操作検出から分離しています。`FileSystemTeamActivityTransport`をSupabase、Firebase、独自実装へ置き換えても、ウィンドウ、ステータス判定、競合検出、Git連携を作り直す必要はありません。
